# Repeated workload comparison — 2026-11-16

The self-contained [HTML report](benchmark-2026-11-16.html) and [raw measurements](benchmark-matrix-2026-11-16.json) replace the earlier resource numbers for the current build. Earlier files remain historical evidence. The [CSV](benchmark-2026-11-16.csv) contains per-launch aggregate and diagnostic metrics.

Supplementary evidence: [one-minute artwork residency](benchmark-residency-2026-11-16.json), one fresh release launch per app with 60 one-second samples (about 62 seconds wall time); and [development-build diagnostics](benchmark-development-2026-11-16.json), two fresh launches in each of four representative states. The report includes both, separately from the three-run release medians. Total: 88 launches.

The baseline is original `develop` at `745ef8285be83fdab3d76e0938f2e2f2eeaeb443`. Its audit-only [adapter patch](tauri-resource-fixture.patch) applies cleanly to that source. It replaces account/session-backed UI responses with generated tracks and a synthetic paused/playing snapshot, assigns an audit application identity and temporary data/cache/WebView locations, and drives existing UI components. No original layout, virtualizer, blur or animation implementation is replaced. The audit build uses dummy application credentials. Native fixtures use the production GPUI views with their account-free preview runtime. No decoder, network stream or audible playback is exercised.

## Workloads and instrumentation

Thirteen states cover 500/5,000/20,000-track idle libraries; artwork idle and scrolling; plain scrolling; compact search scrolling and filtering; navigation/settings with blur; paused/playing fullscreen; and a minimized window. Three independent launches per app/state alternate app order, reversing state order on the second repetition. Every launch receives a fresh temporary backend state directory. OS filesystem/shader caches remain warm. The WebView has its own audit data directory; the adapter clears its local storage. It cannot select production identity or backend state.

After a populated startup marker, the adapter opens the state and waits two seconds to settle. The runner then samples process CPU time and RSS once per second for eight seconds. One CPU core is 100%. RSS includes attributed WebKit XPC helpers, using process descendants plus WebKit processes absent immediately before the launch. That heuristic can include an unrelated concurrently launched WebKit process, so raw process identities/counts are retained. No globally discovered helper or production process is terminated; cleanup signals only the launched process group.

The original WebView content excludes the native titlebar; GPUI includes its titlebar inset. Nominal native window dimensions are 1,200 × 800 desktop and 390 × 844 compact; fullscreen uses the same display. Scrolling moves 1,080 logical pixels/second, reversing every eight seconds. Tauri receives DOM scroll changes and GPUI pointer scroll events, each paced by its own frame callback. This compares application rendering at a common speed, not the physical trackpad/compositor input pipeline.

Synthetic artwork consists of 64 distinct 512 × 512 PNGs generated by FFmpeg testsrc2, repeated across the track collection. The same generated 25 ms loudness/onset/bass/mid/treble lanes drive the synthetic fullscreen-playing fixture. Fullscreen ambient drift is present while paused in both apps. No production artwork was copied for the measurements.

GPUI records actual `MTLDrawable.presentedTime`, CPU renderer submission durations and a glyph-position scene hash. The original records `requestAnimationFrame` timestamps. These are different instruments; their frame rates cannot establish a universal WebKit limit. The glyph hash is useful only for scrolling geometry, not palette/video frame differences. The CPU draw timer excludes application layout, other threads and GPU execution. Static GPUI states can have zero presents after settling, which means the renderer sleeps; it is not zero FPS during interaction.

Startup markers are detected by 10 ms filesystem polling after populated render callbacks. The native internal timer starts after fixture initialization; the external launch-to-marker timer is used for comparisons. Startup is not first-pixel or cold OS-cache latency. Opening callback values are retained in raw data, but adapters resolve different operations/callback counts, especially native fullscreen and the original settings path. No overlay input-to-photon ratio is claimed.

## Findings investigated during collection

The exploratory [before-clock run](benchmark-matrix-before-caret-clock.json) exposed focused compact-search CPU above the original. Actual Metal timestamps showed approximately two frames per second, corresponding to the input caret. The native display clock's one-second idle grace outlasted the 500 ms blink interval, keeping a 120 Hz callback clock awake continuously between sparse paints. The grace was reduced to 50 ms; active animations/input still re-arm it every frame. The final matrix was rebuilt and restarted with a separate binary hash. The exploratory file is incomplete and is not aggregated into the final medians.

## Reproduce safely

Prepare a disposable checkout/archive of the baseline and apply `tauri-resource-fixture.patch`. Build its frontend and Rust release with `tauri/custom-protocol` using dummy build-time application credentials. Build the current native release with `cargo build --release --locked`. Copy the binaries into temporary audit `.app` bundles with distinct audit bundle identifiers. Do not replace or launch an installed release app.

Generate assets and run from the current repository:

```sh
mkdir -p /private/tmp/soundgrammy-benchmark-assets
ffmpeg -hide_banner -loglevel error \
  -f lavfi -i 'testsrc2=size=512x512:rate=1' -frames:v 64 \
  /private/tmp/soundgrammy-benchmark-assets/cover-%02d.png
python3 tools/benchmark_matrix.py \
  --tauri '/private/tmp/soundgrammy-audit-apps/Tauri Audit.app/Contents/MacOS/tauri' \
  --gpui '/private/tmp/soundgrammy-audit-apps/GPUI Audit.app/Contents/MacOS/gpui' \
  --output docs/performance/benchmark-matrix-2026-11-16.json \
  --runs 3 --seconds 8
python3 tools/render_benchmark_report.py \
  docs/performance/benchmark-matrix-2026-11-16.json \
  docs/performance/benchmark-2026-11-16.html \
  --debug docs/performance/benchmark-development-2026-11-16.json \
  --residency docs/performance/benchmark-residency-2026-11-16.json
```

For the residency dataset, use the runner with `--runs 1 --seconds 60 --cases artwork-scroll` and a separate output file. For development diagnostics, copy the normal `cargo build --locked` executable into the temporary debug bundle, then run with `--gpui-label 'GPUI Development' --only-app 'GPUI Development' --runs 2 --seconds 8 --cases idle-5000 scroll search fullscreen-playing`, supplying the release and debug audit bundle executables. Keep those results separate from release comparisons. The report generator accepts an optional `--investigation` paragraph; the checked-in HTML includes the final caret-clock and residency analysis.

The runner accepts only executable paths under `/private/tmp/.../*.app/Contents/MacOS/`, sets isolated fixture/state variables, verifies populated readiness and refuses to mix different binary hashes when resuming. It never opens a production database, session/cache/preferences path or production keychain namespace. The frame/resource adapters require explicit preview/benchmark options; normal app launches do not activate them.

## Limits

No authenticated hydration, live Telegram/ID3 transfers, streaming/codec throughput, audio output CPU/underruns, watts/energy or GPU utilization, hours-long memory run, cold-cache startup, device Android measurements, Windows/Linux/Intel results or installer size is claimed. The original already used Rust for SQLite, network and audio services. RSS includes shared mappings; it is not unique physical memory. Desktop load, display refresh and thermal behavior affect measurements. Idle CPU is near the process-counter resolution, so tiny relative percentages are not meaningful wins/regressions.
